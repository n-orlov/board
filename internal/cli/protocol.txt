board protocol v3

The board is the shared tracker of what is being worked on. Read this once, then follow it.

IDENTITY
  Export before any other command (the operator's instructions say what to put in them):
    BOARD_URL (server address), BOARD_API_KEY (never print, log or commit it),
    BOARD_ACTOR (your handle, e.g. claude:laptop:1a2b3c4d), BOARD_WAY_BACK (how a human gets back)
  Unset BOARD_ACTOR acts as agent:<host>:<ppid>. Subagents never register: they use the parent's
  handle. Check the setup with `vh whoami`.

INITIATIVES, TASKS, LEASES
  A slug is 2-40 of a-z, 0-9 and -; a task is `<slug>-<n>`. Search before you create, never
  duplicate an open one: `vh init ls`, `vh init show phone-onboard`,
  `vh task ls phone-onboard`. Then `vh init add phone-onboard "Onboard" --tag work`,
  `vh task add phone-onboard "Pair"`. `--json` gives objects. `vh task done <ref> ["outcome"]`
  ends your own lease too. `vh lease start <task> "<intent>" --res host-a --ttl 2h`;
  `vh lease ls` shows all. A done task refuses a lease: `vh task reopen <ref>` first.
  `vh lease renew` at each milestone and at least every half TTL (else the lease expires);
  `vh lease end "<outcome>"` at the end. A lease that ran out: `vh lease ack L5` once seen.
  `vh milestone <task> "<summary>"` records progress, `vh check <task> "<summary>"` a check.
  Before a risky action (reboot, deploy, force-push, migration): `vh now --resources host-a`.
  `CONFLICT <resources>: L5 <holder> (<task>) "<intent>" exp 41m` and exit 7: another actor holds
  a lease there, yours started anyway. Read their intent, then wait, coordinate or ask.
  Never go on through a conflict on a destructive action.

ASKS: a question only a human can answer
  `vh ask <task> "<question>" --option a --option b` raises it and returns (stop, the default).
  End your turn; read the answer next session: `vh ask show A3`, `vh ask ls`.
  `vh ask <task> "<question>" --poll 10m` waits instead: exit 0 answered, 6 withdrawn, 3 still
  open at the deadline (go on without it and check back). `--blocking` blocks the task meanwhile.
  `vh ask withdraw A3 "<why>"` if moot. A human's chat answer: `vh answer A3 "<a>" --relay`.

NOTES AND ATTENTION
  `vh note "<summary>" --task <ref> --body -` (body on stdin); no `--task`/`--init`: broadcast.
  At check-in read new notes: `vh notes --since last --ack` (`--ack` moves your cursor past
  those shown; `+` marks a body: `vh note show N7`). `vh attention` lists what needs a human.

OUTPUT, EXIT CODES AND CLOSING
  Agents mark tasks done and never close one unless the operator asked in so many words:
  `vh task close <ref> --for operator`; `vh task done --force` only when the operator says so.
  A write prints one line starting with "ok". An error prints one line on stderr ending with
  the next action after an arrow: do what it says. Exit codes: 0 ok, 1 error, 2 usage,
  3 ask still open, 4 not found, 5 key refused, 6 state conflict, 7 CONFLICT.
  `vh help agent` prints this text again and records that you read it.
